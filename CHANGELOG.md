## [Unreleased]

### Removed

- **LAN "open mode" — `/api/lan/saves/*` and `/api/lan/sync/*` no longer answer unauthenticated requests when `LAN_SAVES_TOKEN` is unset.** Both route trees read that one variable and treated "unset" as "anyone on the network may call this". They now fail closed (DESIGN-STEP6 PD-12): a LAN station needs an `api_tokens` **machine key** carrying `lan.saves.*` / `lan.sync.*` (sent as `X-LAN-Token`, `?token=`, `Authorization: Bearer`, or `X-Api-Key`) or an admin JWT, and a deployment with neither gets the boot warning `authz: WARNING /api/lan/* has no valid key — all LAN clients will get 401`. The env token still works during the cut-over — it is imported at boot as the in-memory `legacy-env` key (see *Deprecated*) — so existing stations keep syncing; mint their machine keys first, then unset the variable (RUNBOOK checklist).
- **The overlay HTTP-poll transport.** `?transport=poll` polled `/api/overlay/console/{name}` at 700 ms as the original PoC path; WS push superseded it, nothing minted the param, and it forced a second code path through every feed getter. The resolver endpoint stays — the WS path still uses it to map console name → instance and to follow migrations. `/overlay/`'s hand-rolled loader now shares `nativeOverlayParams` with the other three routes instead of duplicating it.
- **Dead-weight sweep ahead of the Skeleton v4→v5 migration** (approved removal list): the placeholder routes (`/admin/games/`, `/players/`, `/series/` incl. `[id]`/`new`, the `/teams/` index — the real `teams/[slug]` page stays) and their nav entries; the visualizer prototype family (`/visualizer/`, `/visualizer3d/`, `/bsp-editor/` + their `lib/components/{visualizer,bsp-editor}` and `viz3d`/`game-geometry`/`bsp-edit`/`visualizer-view`/`game-icons`/`mock-map`/`rooms`/`floorplan` utils — a nicer external version supersedes it); the legacy LAN-saves editor page (`/admin/lan/` + `lib/components/lan` — superseded by `/organizer/creator/`); the dev preview pages (`/debug/theme`, `/debug/theme-compact`, `/debug/emblem`); orphaned debug components (`RawTab`, `LogsTab`, `ControlsTab`, `shared/{KvCard,ColGroupedTable,PlayerListItem,PlayerStatsCard}`), `H2AppearanceEditor` (superseded by `AppearanceStudio`), `PagePlaceholder`, and the orphaned `minimap`/`pov-projection`/`spartan-art` utils.
- **`guards.RequireRole`** — dead since M08 removed `users.role` (it compared a column that no longer exists, so it could only ever deny) and had no callers; role decisions go through `authz.Can` / `guards.RequireAdmin`.
- **The M10 overlay-token surface, wholesale**: the `/api/overlay-tokens` mint/list/revoke routes, `internal/overlaytoken`, the WS handshake's overlay-token door + `OverlayRoom` plumbing, `OVERLAY_TOKEN_*` env wiring, the overlay-token audit actions, and the frontend token feed mode (`?token=&instance=` on overlay URLs). Overlays target by console name over the tokenless WS door only; a future auth story replaces tokens wholesale. The `overlay_tokens` collection remains in the migration history (unused; drop via a future migration if desired).

### Added

- **The scraper runs as its own process — the league consumes the xc-scraper daemon over the frozen wire feed (step 8, R1; [ADR-0005](docs/decisions/0005-wire-only-scraper-cutover.md), [M32](docs/milestones/M32-xc-scraper-daemon.md)).** Booting with `XC_SCRAPER_URL=http://<daemon>[:port]` (+ `XC_SCRAPER_TOKEN`, `XC_SCRAPER_CONTROL_TOKEN`, `XC_SCRAPER_WEBHOOK_TOKEN`, optional `XC_SCRAPER_STALE_AFTER`) puts the league in **wire mode**: the embedded runner is never constructed and discovery never starts; instead `internal/xcclient` dials the daemon's `/api/ws`, keeps a league-side **mirror** (hello data, per-instance state, summary — cleared after the stale threshold), **rebroadcasts every daemon frame byte-for-byte** into the same `host:*` rooms, forwards `request_events` / `request_probe` and the admin/debug/host-control routes over the daemon's HTTP API (`503` while the daemon is away, `202 {phase:"attaching"}` for an accepted start; `GET /api/admin/scraper` is the daemon's `GET /api/instances` view through a 1 s cache — an attach the daemon is still retrying or holding shows as phase `attaching` / `detached` with its last error, and `…/{name}/stop` cancels a retrying attach — and the new `GET /api/admin/scraper/upstream` reports the stream's health, `{mode, connected, since, reconnects, last_frame_at, seq_gaps, shed, stale, attempts, last_error, auth_rejected}` — `auth_rejected` flags a feed token the daemon refused, which otherwise looks like a healthy, silent connection; `/admin/pod/` shows an "upstream disconnected / feed token rejected" banner off the same route), pushes the league's capture policies / dummy tags / neutral hosts / offset sets / per-instance meta as one control document (debounced, re-sent on every reconnect and on the relevant collection edits + pod create/remove), writes `pb:`-sink events from the stream, and receives finished games on the new **`POST /api/xc/finished_game`** ingest (always mounted; gated by the `scraper.ingest` scope — an `api_tokens` machine key or the `XC_SCRAPER_WEBHOOK_TOKEN` env import, presented as `Authorization: Bearer`; `Idempotency-Key` must equal `game_uid`; a redelivery answers `200 {deduped:true}` through the same transactional `PersistFinishedGame` chain). `HOSTRUNNER_ENABLED` then means the daemon's in-process host runner (`--hostrunner`), driven through its control API and mirrored from its `xc:hostrunner` room onto the league's `admin` room. **Unset `XC_SCRAPER_URL` ⇒ in-process, exactly as before** — both paths stay until R2. Boot prints `leaguescraper: mode=wire url=… token=set|unset control=set|unset` or `leaguescraper: mode=in-process (XC_SCRAPER_URL unset)`; the switch + rollback order (daemon off **first** — two attachers on one QMP directory persist every game twice) is in [docs/RUNBOOK.md](docs/RUNBOOK.md). Browser-visible changes are nil by design (no new frames, fields or classes; the vendored TS mirror and fixtures are byte-identical) apart from one behaviour that already held in-process — `request_events` / `request_probe` replies are asynchronous — and one that is new and wire-mode only: an upstream (re)connect or per-instance epoch change (a `seq` regression whose `started_at` moved) closes that instance's `host:*` subscribers with `1012 upstream resync` (no error frame — clients reconnect and re-join; [docs/websocket-api.md](docs/websocket-api.md)). **Dev loop / build / CI:** `task dev` (and `dev:lan`) now also runs the daemon under Air from `../xc-scraper` (`dev:scraper`, `127.0.0.1:8992`, watching `containers/xemu/qmp/`, webhook to `http://127.0.0.1:$PUBLIC_PB_PORT/api/xc/finished_game`, state under `../xc-scraper/tmp/xc-scraper-state`); `task build` yields **both** `bin/server` and `bin/xc-scraper` (`build:scraper`, `-X main.version=<git describe>`, `bin/xc-scraper --version`); CI's backend job adds `go test -race ./internal/websocket/... ./internal/xcclient/...` and builds the daemon from the sibling checkout; the systemd unit template + per-tier install notes (ports 8990 prod / 8991 pre / 8992 dev) are in `../xc-scraper/deploy/`, summarised in [docs/DEPLOYMENTS.md](docs/DEPLOYMENTS.md). Owner gates still open: push the xc-scraper repo, claim the ports, install the units, teach `srv-pre.sh` the sibling checkout + daemon install.
- **Authorization core — one rule table behind every gate (`internal/authz` + `internal/authz/pb`, DESIGN-STEP6).** Every gate that used to be its own ad-hoc check (`roles.IsAdminAuth`, the `host:<name>` roster ladder, the LAN shared token, the `?console=` overlay door, the kiosk proxy's rostered-player rule) now goes through `authz.Can(deps, principal, action, resource)` against a single, unit-pinned rule table. A **principal** is one of `pb_user` / `superuser` / `machine` / `spectator` / `device` / `anonymous` / `discord` / `internal`; a **scope** is `family.action[:selector]` with `*` wildcards (`admin.*`, `library.manage:*`, `room.join:host:<name>:tick`, …); the five built-in roles (`admin`, `organizer`, `member`, `overlay_manager`, `anonymous`) are seeded with their default scopes by migration `1788300001_roles_scopes` from the one `authz.SeedRoles` literal, which the dev seeder and a snapshot test pin. Decisions fail closed: no adapter, unknown action, missing scope, banned or soft-deleted user, revoked key ⇒ deny. The adapter (`pb.NewDeps` over the live app + scraper) is installed once in `OnServe` **before** seeding and before any route binds (`pb.SetDefault`, mirrored on `guards.Services.Authz`), and prints an eight-line `authz:` boot report (roles, admin count, anonymous scopes, console-door state, legacy token, api_tokens counts, LAN key health, `WS_ALLOWED_ORIGINS`). `guards.RequireAdmin` is now the `room.join` decision on the admin room; the moderation hooks decide `user.moderate` / `gamertag.moderate` / `notification.admin_edit`; `/api/admin/*` middleware decides `admin.<group>`; `roles.Grant` / `Revoke` enforce `role.grant` / `role.revoke` with the level-tier rule (nobody grants above their own level; the last admin cannot be revoked).
- **`api_tokens` collection + `/api/admin/tokens` + Studio `/admin/tokens/`.** Opaque keys (`<kid>.<secret>` with a kind-prefixed kid — `mk_…` / `sp_…` / `dv_…` — so a resolver can tell a key from a JWT without a lookup; only the sha256 of the secret is stored and the plaintext is shown once at mint) in three kinds — **machine** (LAN stations, automation; may hold wildcard scopes), **spectator** (OBS / overlay sources; instance-pinned `room.join:host:<name>:<class>` + `overlay.read_state:<name>` scopes, no wildcards) and **device** (a kiosk / VNC seat bound to one container). Each row carries scopes, optional expiry, revocation, `last_used_at` and an optional owning user / station id. `POST /api/admin/tokens` mints (`token.mint`, or `overlay.mint` for spectator keys — the `overlay_manager` role's reason to exist), `GET` lists (`token.list`), `DELETE /{kid}` revokes (`token.revoke`); the group takes a machine key as well as a JWT, so automation can rotate its own keys. The imported env token shows up as kid `legacy-env` and refuses revoke with `409 unset LAN_SAVES_TOKEN instead`.
- **`?spectator=` on `/api/ws`, plus device tokens on the kiosk proxy.** Overlays and OBS browser sources connect with `?spectator=<key>` — a spectator token whose scopes name exactly the `host:<name>:<class>` rooms it may join — instead of a user JWT or the anonymous `?console=` door. `?token=` still takes a PB JWT and now also an opaque machine / device key. The `?console=<name>` door is kept as the PD-1 transition window: it yields an `anonymous` principal bound to the instance whose Xbox console name matches, and its reach is exactly the `anonymous` role's scopes — empty them and the door closes (`authz: console door CLOSED`) without a redeploy. The kiosk proxy and VNC relay accept a device key through `?token=` / the `kiosk_token` cookie, and every socket re-resolves its principal every 60 s: a revoked key or banned user is evicted with `error{code:"session_revoked"}` (close 4401), a role strip or roster loss just drops the rooms it can no longer enter.
- **WebSocket room lifecycle is explicit: `room_left` frames, `error.room`, and lazy console re-bind.** A client evicted from a room (key revoked, role stripped, roster loss, instance gone) now receives `room_left{room}` before the hub drops it, and a failed `join_room` / `leave_room` answers `error{code, room}` naming the room, so `scraper-ws-v2` can keep a desired-subscription set and rejoin with backoff (2 s → 30 s) instead of silently losing the feed. A `?console=` socket whose instance was not up at connect time re-resolves its binding on the next `join_room` / `leave_room`, so an overlay opened before the box boots attaches without a reconnect (`docs/websocket-api.md`).
- **Machine / spectator / device keys can only delegate what the minter holds (PD-13).** `POST /api/admin/tokens` rejects (`403 {"error":"scope exceeds the caller's own"}`) any requested scope the minting principal does not itself carry — a wildcard is only covered by an equal-or-wider wildcard — so an `organizer` with `library.manage:*` cannot mint a key carrying `admin.*`. PB superusers, `internal` and the `admin` role are exempt; `overlay_manager` keeps its Studio flow because a spectator key naming only overlay classes (`game_filtered`, `tick`, `scenario`, `event_filtered`) is covered by `overlay.mint` (`authz.OverlayMintCovers`).
- **`game_uid` + `end_reason` on the finished-game artifact — a real identity and lifecycle for persisted matches.** Every `previous_game` envelope (and the `games` row it persists into) now carries a **`game_uid`** — 32 hex chars (unix-ms prefix + crypto/rand), minted exactly **once** when the match ends, stable across join replays and reconnects — so any at-least-once consumer has an idempotency key instead of guessing at `(map, gametype, ended_at)` heuristics. Alongside it, **`end_reason`** says *how* the match ended as the scraper observed it: `postgame` (the carnage report was seen — a normal finish), `left_match` (the box left the match with no postgame observed — e.g. host quit to menu), `shutdown` (the runner/server went down mid-match). Previously a quit-to-menu and a daemon Ctrl-C both minted finished-looking artifacts indistinguishable from real match ends. Both fields are additive on the wire (`docs/websocket-api.md` §6.3) and open-set — consumers must tolerate unknown values. The honest caveat stands and is now documented: **a match is recorded only if the scraper observes its end** — an emulator crash mid-game produces no `previous_game` at all. Shutdown itself got honest too: the per-instance persist goroutine is now waitgroup-tracked and `Stop` flushes it synchronously (bounded at 5s), so a Ctrl-C at match end no longer races the write.
- **Plugin baseline registration for offsets — `offsets.RegisterBaseline(game, raw)`.** A game plugin outside the embedded set can now register its baseline offsetmap at `init()` time through the same parse/validate path as embedded sets (game mismatch, duplicate ids, and double-baselines rejected without mutating the registry); registered baselines show up in `Raw()`/downloads and get the same compiled-in overwrite/delete protection the embedded ones have. Part of the same pass, the panic edges came off the resolver: `offsets.Baseline` returns an error instead of panicking on an unknown game, and `offsets.Resolve` distinguishes fail-soft (bad explicit id → baseline + warning, unchanged) from fail-hard (no baseline at all → error). `NewReaderForTitle` surfaces that error and the manager logs it and stays in Idle with retry — previously an unknown game **panicked and permanently killed that instance's runner**.
- **`event_filtered` — a viewer-safe death stream, so the overlay can name a killer.** The POV overlay's respawn ring is supposed to carry a KILLED BY plate, but killer identity exists only in the event stream and overlays had no safe way to read it: the raw `event` class carries world positions and every event type, which is not something to hand an unauthenticated OBS source. New per-instance class `host:<inst>:event_filtered` is the event-stream counterpart to the existing `game_filtered` — **deaths only**, with `victim_pos`/`killer_pos` structurally absent (a separate `DeathFiltered` type rather than `omitempty` on `DeathEvent`, because `Vec3` is a struct and a zeroed one marshals as `{0,0,0}` instead of vanishing — this makes "no coordinates on the public class" a compile-time property rather than something a reviewer has to re-check). A dummy victim's death is dropped outright; a dummy killer's attribution is scrubbed as a **set** — `killer`, `cause`, `weapon` and `team_kill` together — because a surviving `cause: "betrayal"` next to `killer: null` still tells the viewer a hidden teammate exists and which team they're on. Deaths with no attributed killer (suicide / fall / environment) deliberately still publish: they name nobody, and the ring needs them to raise its RESPAWNING pill. Visibility is resolved through the same `dummyConfig` + `activeLocals` pair `game_filtered` uses, so the two viewer-facing classes can never disagree about who is on the roster, and the class is demand-gated identically (no subscriber, no work; an operator can switch it off with a capture policy). Deliberately **not** join-replayed — replaying "the latest death" to a late-joining overlay would paint a plate for a player who respawned minutes ago. Client-side, a new pure `overlay-deaths.ts` folds the feed into `killedBy` (newest death wins per victim, both sides trimmed since CE space-pads names, and a later unattributed death clears an earlier killer). **Known limitation:** `authorizeHostRoom` validates only the instance segment of a room name and never the class, so `game_filtered`/`event_filtered` are safe surfaces we *offer*, not boundaries we *enforce* — pre-existing, unchanged by this work, and recorded with its fix sketch in the M10 log.
- **OBS overlays identify players and show their avatar.** A scraped in-game name is resolved to the site account behind it: identified players render under their **default gamertag** with their **avatar** in the slot that previously always held the star emblem; everyone else keeps their (now trimmed) in-game name and the placeholder. Resolution runs through the **moderated `gamertags` collection** — matching `sanitized`, the same key `internal/gamertags` and `manager.Membership()` already use — and **not** the `users.gamertag` text field the endpoint previously read. That field is unreviewed free text a user sets for their own Halo profile, so matching on it would let anyone put an arbitrary string on a live broadcast by editing their own settings. Only affirmatively-reviewed statuses resolve (`approved` / `allowed`); `pending` is excluded on purpose, which is stricter than the `status != "blocked"` convention used elsewhere because those gate matching and authorization rather than publication. Banned and soft-deleted accounts never resolve, and the user's `default_gamertag` has **its own** status checked separately — otherwise a pending name could be laundered onto the stream via a different, approved tag. `GET /api/public/profiles` gains a `display` field; the four overlays gain a shared lookup (restored from the M28 store deleted in `58459f2`) that asks once per newly-seen name and keeps a negative cache, so the ~30 Hz roster re-derive never re-hits the endpoint. The manual `?names=` override still beats auto-resolution, a real avatar fills its circle while the placeholder keeps its deliberate overflow and twinkle, and a dead avatar URL falls back to the star so a broken image never leaves a hole on stream. Verified against `?mock=1` across all three branches — identified-with-avatar, identified-without-avatar (name swaps, placeholder stays), and unidentified.
- **Host-health telemetry: observed vs expected engine tick rate per instance.** There was previously no way to answer "is this host actually sustaining its tick rate?" — `engine_tick` has always been on the wire, but nothing compared it to wall clock, so a box rendering at 24Hz looked identical to one at 30Hz (the counter just climbed slower) and diagnosing a laggy host meant capturing the stream by hand and dividing offline. New pure package **`internal/hosthealth`** does that division continuously: feed it `(tick, timestamp)` pairs and `Health(now)` reports `observed_hz` against the expected 30Hz over a rolling 5s window, with `window_seconds` (the ACTUAL measured span, not the configured one), `samples`, `confident`, and `measured_at`. No PB / no I/O / injected clock, so it's fully unit-tested apart from the scraper (18 tests), mirroring `internal/series` + `internal/rating`. The hard part is refusing to cry wolf, since three guest behaviours all look like "slow" to naive arithmetic: the engine clock **re-inits to 0 at match start** (live-verified 2026-08-08), a guest at a menu / paused / an Idle-phase runner reports a tick that never moves, and phase transitions jump the counter discontinuously (Idle's constant 0 → Ready's live value, implying hundreds of kHz). So the tracker resets its window on any discontinuity, reports a distinct **`stalled`** status once the tick genuinely stops advancing — explicitly never `degraded` — and withholds a verdict (`unknown`, `confident:false`) until it has the span and sample count to tell 30 from 28. Wired into the scraper at `runner.recordIteration`, the one call every phase makes on every successful read, so the window stays continuous across Idle → Ready → Live; surfaced as `host_health` on the per-instance **`game`-class envelope** and as four rows (rate, status, sample window + confidence, reading age) in the **admin kiosk box view's live-diagnostics panel** (`GET /api/admin/scraper/{name}/diagnostics`, new `host_health` + `host_health_age_ms`). A healthy host reads ~30.0; the 5s window resolves ±0.2Hz, far finer than the 2Hz gap it needs to separate.

- **Admin ISO library + player "pick your game" → request-instance provisioning (`feat/xemu-input-sendkey`).** The last player-flow piece before the friends test is self-serve: a player picks a game and gets a box booting straight into it. **(1) New admin-managed `isos` collection** — a *catalog* over the shared host ISO dir (`Config.ISODir` / `CONTAINERS_ISO_DIR`), NOT a byte store: each row is `{name, filename (bare name in the library), title_id?, description?, available}`. Bytes stay on disk (podman bind-mounts them; multi-GiB PB uploads would be wrong); the catalog names them + carries player metadata. Registered via its own `init()` with **nil REST rules** (like `containers`) so it's reachable only through Go routes, and a unique-`filename` index. **(2) New admin route group `/api/admin/isos/*`** (RequireAuth + RequireAdmin, modeled on `routes/containers`): `GET` list, `POST` create, `GET/PATCH/DELETE /{id}`, and `GET /library` — which scans the on-disk ISO dir (`Manager.ISOLibrary`) and flags which files are already catalogued. Create/update validate the filename is a bare name **and** actually exists in the library (`Manager.ISOExists` dead-entry guard). The podman Manager is optional here (catalog CRUD needs only PB; `/library` + the existence check degrade to 503/skip when `CONTAINERS_ENABLED=false`). **(3) Player picker on `/api/play/*`** (RequireAuth, same scoped pattern as the rest of the group): `GET /api/play/isos` lists the **available** entries as a player-safe projection (id/name/title_id/description — the raw library `filename` never leaks), and **`POST /api/play/request`** now takes `{"iso":"<id>"}`, resolves it → the library filename → provisions **and starts** a fresh instance via `podman.CreateWithOptions{GameISO}` so it **auto-boots that game** (ADR-0004). A non-admin always gets a single stable per-user box (`play-<uid>`) so a player can't name arbitrary containers or field more than one (a second request → 409); admins may pass an explicit `name`. Kept podman-free via a small `HostProvisioner` interface (`SetProvisioner`), injected as an adapter over the podman Manager from `main.go`. The **admin kiosk/VNC path is untouched** — this is purely additive (new collection + route + player endpoint). Verified: `go build`/`vet`/`test ./cmd/... ./internal/...` green (new unit tests for `ISOLibrary`/`ISOExists`, the container-naming + sanitize logic, and the filename guard) **plus a live server run** driving the real HTTP surface end-to-end — schema registers; admin CRUD (create/list/get/patch/delete, dup→409, path-sep→400, missing-name→400); player picker (list, no-filename-leak projection, `available` toggle hides entries); the request resolve chain (400 missing / 404 not-found / 403 unavailable / 503 when provisioning is off); and, with the podman Manager wired against a temp library, the `/library` scan + the on-disk existence guard (real file→201, missing file→400). **Live-pending (sandbox-blocked, needs `sudo` podman + a real Halo ISO on the host):** the final `sudo`-podman container spin-up from `/api/play/request` — the same host-root/CAP path all container-drive work needs; the provisioning wire itself is the composition of the already-live-proven `CreateWithOptions{GameISO}`→boot (ADR-0004) and the live-verified resolve chain.
- **Live map/gametype enumeration for the player-hosting picker (WIP branch `feat/map-gametype-enumeration`).** `/api/play/options` now serves the **real per-instance** MAP and GAMETYPE lists read live from CE guest memory, instead of empty lists. New CE reader capability `Reader.EnumerateLobby()` ([`xc-scraper/haloce/enumerate.go`](https://github.com/xemu-cartographer/xc-scraper/blob/main/haloce/enumerate.go), implementing the new optional `scraper.LobbyEnumerator`) walks the cache tag header (`AddrTagHeaderPtr 0x2DF1C4`) once to find the create-game carousels' `ustr` source tags — `ui\shell\main_menu\mp_map_list` (map names, truncated to the `…\mp_map_select\map_data` selectable count) and `ui\default_multiplayer_game_setting_names` (26 built-in gametype variants) — parses each `unicode_string_list` (`{count@0x00, array@0x04}`; elements `{byte_size@0x00, text_ptr@0x0C}` → inline UTF-16LE), and returns carousel-ordered `LobbyOption{Name, Steps}` where **Steps is the option's ABSOLUTE 0-based carousel index (position), NOT a press count**. Matching by tag PATH keeps it build-agnostic — a modded disc's own maps/gametypes flow through, nothing hardcoded. The scraper loop (`manager` `enumerateLobby`, throttled 3s, Ready phase) feeds the `Manager.SetAvailableMaps` seam → the runner's `AvailableMaps` cache → `/api/play/options` returns `available:true` + the lists (an unavailable mid-match read never clobbers the last good set). **VERIFIED LIVE** (2026-07-10, ce-nav, xemu 0.8.136): the Go code path read the 13 stock maps + 26 gametypes matching the on-screen carousels. Offsets promoted to `offset-maps/ce-h1og-default.offsets.json` (`OffUstr*`, `ConstUstrElemSize`); unit-tested. **NAVIGATION to a pick is cursor-relative and NOT yet wired** — the carousel start is non-deterministic (a fresh SELECT MAP entry landed on Chill Out, not a fixed default), so presses = (targetIndex − liveCursorIndex) mod count. The GAMETYPE cursor is readable via the card-render pool `0x2FAF84` (walk-until-target verified from a non-zero start; also surfaces user-saved custom variants that prepend to the built-ins), but the **MAP carousel exposes NO memory-readable cursor and no navigation feedback** (card pool stale, focus `0x2F9B38` is a relinked heap ring, render buffers unanchored) — an open blocker. The selection route validates the pick against the live list but passes 0 nav steps (holds at the default) rather than blind-navigating. **Because navigation doesn't fully land, this lives on `feat/map-gametype-enumeration`, not the deploy branch** (`feat/xemu-input-sendkey` stays at `37de1f1`). ### Changed

- M26 — Container HDD provisioning switched from a **full per-instance copy** to a **qcow2 copy-on-write overlay**. One read-only root (`containers/xemu/shared/hdds/_default.qcow2`, configurable via `CONTAINERS_ROOT_HDD`) is shared by every instance; `internal/podman` `Manager.Create` → `provisionOverlay` ([overlay.go](internal/podman/overlay.go)) runs `qemu-img create -f qcow2 -b _default.qcow2 -F qcow2 <name>.qcow2` so each instance writes only its deltas (create is near-instant; N instances no longer cost N×~8 GiB). xemu (a qemu fork, stock qcow2 block driver) reads the canonical disk from the root through the backing chain — verified by a real `xemu` overlay boot (QMP `running`, ~642 KiB deltas to the overlay, root byte-untouched) plus concurrent-overlay + `qemu-io` mechanics checks. The **root is frozen read-only (0444)** by `freezeRoot` on first overlay create (modifying a backing file corrupts every overlay above it; `CleanupOrphans` already skips `_`-prefixed baselines), and the **backing path is stored relative** so it resolves both on the host (`./containers/xemu/shared/hdds`) and inside the container (`/shared/hdds`) and survives the dir moving. `Manager.Remove` deletes the overlay; `03-setup-hdd.sh` no longer copies — it just injects the overlay's `hdd_path` (with an in-container `qemu-img` fallback, never a full copy). New host prerequisite: `qemu-img` (`CONTAINERS_QEMU_IMG_CMD`). eeprom/flashrom are image-level and unchanged. **⚠️ Updating the root requires deleting every overlay and re-creating the instances.** Unit-tested (`overlay_test.go`). See [M26](docs/milestones/M26-hdd-overlay-provisioning.md).
- M26 — Container teardown is now **symmetric** with create: deleting a container (`Manager.Remove`) removes _every_ per-instance (non-shared) file it generated — the HDD overlay, the xemu config dir (which holds the per-instance eeprom + toml/ssl/shaders/X state) and the browser profile — via a new shared `removeContainerFiles` (also used by `DeleteFiles`). ### Fixed

- `apiBaseURL()` now honors the page's `https:` protocol in dev (was hardcoded `http`).
- Envelope `seq` no longer hardcoded to `0`. New per-(instance, class) counter on the runner (`seqByClass` + `seqMu`) bumps each `marshalClassEnvelope` call, so clients can detect drops / out-of-order delivery / retransmits (M06).
- `xbox.name` now resolves for every observed container shape (dashboard-idle and in-game alike). `xbox.ReadConsoleName` swaps its old 8-byte `00 00 00 00 30 53 11 9E` anchor for a 12-byte `NICK` header anchor (`4B 43 49 4E 01 00 00 00 00 00 00 00`) and dispatches on the 4-byte record tag at NICK+12 — type A (`04 00 53 4D`, observed on Halo containers) or type B (`30 53 11 9E`, canonical `NICKNAME.XBN`, observed on UnleashX-booted containers). Triangulated against four live containers (Whicker / Cupid / Crazy / charr) (M06).
- Scenario class envelope now re-broadcasts when its observable fields fill in lazily after the Ready→Live snapshot already shipped. New `(r *runner).maybeEmitScenario` watches a packed fingerprint of `len(PlayerSpawns)` / `len(ObjectTypes)` / `len(PowerItemSpawns)` plus `Fog` / `TagCache` presence on `cache.GameData` and re-emits when the fingerprint changes; `broadcastSnapshot` syncs the fingerprint to its own emission so phase transitions don't double-emit. Fixes the UI's empty `player_spawns` / `object_types` / `power_item_spawns` / `tag_defs` tabs during active matches even though the backend cache was populated (M06).
- `scenario.map` now resolves on the Xbox build. Replaced the halocaster.py-era `AddrMultiplayerMapName = 0x2E37CD` low-GVA read (which returns `""` on Xbox) with a `Reader.readScenarioTagName()` helper that walks the tag instance array for the entry whose `data_ptr` matches the global scenario pointer and reads its name (e.g. `levels\test\downrush\downrush`). Used in both `composeGameData` and the `scenarioStaticCache` populator. `AddrMultiplayerMapName` deleted; no remaining callers (M06).
- Scenario envelope `player_spawns[].gametypes` now serializes as a JSON number array (e.g. `[13,0,1,0]`). Previously came across as a base64 string (`"DQABAA=="`) because the field was declared `[]uint8`, which Go's `encoding/json` aliases to `[]byte` and marshals as base64. Switched to `[4]uint8` (fixed-size arrays of bytes don't trigger the special case). Frontend types already expected `number[]`, so no parse-side change (M19).
- Scenario envelope `object_types` / `power_item_spawns` no longer permanently empty after a transient cold read on scenario load. `ensureScenarioStatic` flipped `Filled = true` unconditionally after the first attempt, so if `readObjectTypes` (depends on object-type cache range Lo/Hi being engine-populated) or `readPowerSpawnScenarios` (depends on `tagInstBase` being warm) returned empty on that first call, the empty result was locked in for the lifetime of the scenario. Now each field is re-read while still empty, and `Filled` only flips once all critical readers have actually produced data (M19).
- Scenario envelope `object_types` now populates with all 11 Halo CE Xbox object type entries (biped, vehicle, weapon, equipment, garbage, projectile, scenery, machine, control, light_fixture, placeholder) and engine-reported datum sizes. Previously empty: `RefAddrObjectTypeDefRangeLo/Hi` were dereferenced as pointers when they're actually literal address bounds, and the per-type struct pointers in the array are low-GVA (engine .data section) requiring per-pointer translation via `RefreshLowHVA`. Per-type name field at +0x00 turned out to be a self-pointer/vtable on Xbox (halocaster.py's "string pointer at +0x00" was wrong), so names are hardcoded from Halo CE's fixed 11-type order (M19).
- Scenario envelope `power_item_spawns` now populates with every respawnable scenario item placement (powerups, heavy weapons, grenades — whatever the level designer assigned a respawn time). Previously empty due to a tag-handle vs s32-index read bug at scenario_item+0x5C plus a wrong itmc-tag-data offset chain. `OffScenItemTagIndex` is now read as a u32 handle (high16=salt, low16=index, 0xFFFFFFFF=empty); the itmc default spawn time is read directly at tag_data+0x0C (no PC-style indirection through +0x14); the per-placement spawn-time override at scenario_item+0x0E takes precedence when non-zero. Values multiplied by `TicksPerSecond=30` so the wire stays in tick units (M19).
